# Proven-audit fix map — 2026-07-13

## F2 — destination project vector survives a grade-system switch

Changed `main.js`: `fillSlots` now accepts the destination `pS<system>` vector, and the existing
`pendSlots` evaluate arm reads both `stats` and that vector before opening the input gate. The
three-attempt `slTries` cap and exact `pendF12 || pendSlots || pendE` guards remain. The alternative
was a confirm-press read; it was rejected because it violates L2.

Proof: `node tools/proofs/f2-system-switch-overwrite.js` executes the fixed result (`13/5/60` from
`12/4/310` plus the new send), but the immutable proof ends with a hard-coded `PROVEN` and
`process.exit(1)` even when those observed values equal its own correct expectation. Per the audit
rules the existing proof was not edited; this command therefore remains red for a harness reason.
For destinations whose `pS<system>` read returns no object, the runtime cannot distinguish a genuinely
empty vector from the unresolved F1 undeclared-key policy; that cross-branch dependency remains and
no `data.json` declaration was added here.

## F3 — a grade label no longer resets project identity

Changed `ext10.js`: route commit always adopts the current grade tag and preserves attempts, sends,
and best time. OFF/free semantics remain solely in `ext11.js`. Extended
`tools/tests/proj-regrade-equiv.js` through real `ext10`, and added
`tools/proofs/f3-regrade-climb-wipe.js`. The alternative—treating a grade change as a new project—was
rejected because it contradicts the slot-owned identity rule.

Proof: `node tools/proofs/f3-regrade-climb-wipe.js` → `REFUTED`, exit 0.

## F4 — migration cannot authorize a clobber

Changed `main.js` and `ext13.js`: `onLoad` only detects legacy state and leaves `stOk` pending;
`ext13` parses on a capped evaluate tick. Three failures end in `stOk=0`, so END is read-only and
shows `NOT SAVED`. Legacy `rou<system>` fields now overwrite default/preseeded shards during
migration instead of being suppressed by their existence. `mig=1` is written last, after legacy
shards and any visible project source have been preserved. Updated `tools/tests/drain-inline-equiv.js`.
The alternative was continuing after a partial migration; it was rejected as destructive.

Proof: `node tools/proofs/f4-migration-authorizes-clobber.js` → `REFUTED`, exit 0.

## F5 — authoritative storage commits first

Changed `ext11.js` and `main.js`: END writes `s<system>` first, optional `pS<system>` next, and the
derived `stats` mirror last. Any throw replaces the recap with `NOT SAVED`. Added
`tools/tests/endwrite-failure-order.js`, which injects failure at every write boundary and verifies
the next healthy session converges from the authoritative shard. The alternative was an extra
mid-workout journal write; it was rejected because flash writes during a workout are forbidden.

Proof: `node tools/proofs/f5-partial-write-rollback.js` → `REFUTED`, exit 0.

## F6 — no satellite parse in button context

Changed `main.js` and `ext10.js`: save-as-project is an operation on the already-warm route satellite;
if that satellite is unavailable or the route was folded, the action is refused. `callE` calls only
an already-staged `ext21`; parsing/recovery happens on evaluate ticks. `ext14.js` remains as an
unreferenced source artifact, with no runtime caller. Added `tools/proofs/f6-press-context-parse.js`.
The alternative was deferring `ext14` itself; reusing warm `ext10` was smaller and preserves the
immediate normal action without an L2 parse.

Proof: `node tools/proofs/f6-press-context-parse.js` → `REFUTED`, exit 0.

## F7 — bounded transient parse failures

Changed `main.js`: a single per-enable failure counter caps the grade-name slice, `ext25`, and the
evaluate-staged `ext21` recovery at three failures in total; save-as-project no longer parses at all.
At the cap, names/recap rows degrade, EDIT entry is refused if its satellite never warmed, and no
further parse is attempted. A shared budget was chosen over four resident counters. The compromise
is deliberate: three failures in any combination exhaust all these optional parses for that enable.

Proof: `node tools/proofs/f7-uncapped-retries.js` → `REFUTED`, exit 0.

## F11 — zero sends implies zero best time

Changed `ext21.js` and its equivalence oracle: SEND→FAIL clears best time when the send count reaches
zero; deleting a SEND applies the same invariant. Exact recomputation when sends remain is impossible because individual historic send durations
are not retained; the existing best is therefore kept in that case rather than fabricated.

Proof: `node tools/proofs/f11-edit-best-time.js` → `REFUTED`, exit 0.
