# PR2 notes — F1 and F12

## Changes and cost

- `data.json` and `data.default.json` now declare `pS1`–`pS9`, copied exactly from `pS0`: indices 0–14 default to `0`, and grade indices 15–19 default to `-1`.
- The existing `onLap` now returns immediately when `isPaused`, so a paused callback cannot arm `extLapPending` and create a SEND after continue.
- `data.json`: 1,999 B → 3,287 B, a +1,288 B flash-schema delta. These declarations are data, not code, so F1 costs zero resident bytes; the tradeoff is that the storage layer touches a larger flash object.
- q-display resident `main.js`: 7,060 B → 7,072 B, a +12 B delta from the F12 guard. This remains below the 7,100 B clean limit with 28 B headroom.

## On-watch confirmation after flashing

Select a non-zero grade system (for example system 1, UIAA Sport), configure a project slot, log a project route, end and save the activity, then restart Climb Logger and confirm that the slot's attempts, sends, best time, and grade survived.

Pull `b:/zapp/storage/climbl01/data.jsn` and inspect the matching top-level key (for example `pS1`). It must contain the saved slot values in attempts `[0..4]`, sends `[5..9]`, best time `[10..14]`, and grade `[15..19]`; merely seeing an untouched default vector is not sufficient evidence of persistence.

The firmware question of whether `onLap` is dispatched while paused remains open, but it no longer changes app behavior: the guard rejects the callback if it arrives.
